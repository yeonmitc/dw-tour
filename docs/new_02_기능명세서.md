## 2. 바로 접속과 관리자 권한

주소 접속 시 로그인 화면 없이 필리핀 예약 목록을 연다. 일반 예약 조회·신규 추가·상세 수정은 관리자 세션 없이 사용한다. 예약 삭제, 원본 이관/검토 확정, 관리 설정 변경처럼 관리자 권한이 필요한 버튼을 누르면 비밀번호 한 칸의 모달을 띄운다. 새 Supabase 프로젝트의 고정 관리자 계정으로 비밀번호를 검증하고, 인증되면 모달을 닫고 원래 동작을 계속한다. 비밀번호를 취소하거나 검증에 실패하면 데이터 변경을 하지 않고 기존 화면과 입력을 유지한다. 로그아웃은 관리자 권한만 해제하며 일반 화면은 계속 볼 수 있다. 공개 회원가입과 역할 선택 화면은 없다. 비로그인 일반 쓰기의 접근 범위와 삭제의 서버 권한 검사는 별도로 설정한다.

## 3. 국가별 예약 관리

### 공통 예약 동작

- 필수: 국가, 대표자 또는 식별 가능한 손님 원문, 예약 생성 출처. 가져온 원본의 코드·서비스 날짜·인원은 없거나 모호하면 빈 값과 검토 상태를 허용한다. 신규 예약은 코드 자동 추천을 사용하거나 수기로 코드를 입력할 수 있다.
- 내부 UUID로 예약을 식별한다. 같은 예약 코드가 다른 손님/기간/국가에 다시 나와도 입력과 검색이 가능하다.
- 예약에는 여러 손님, 호텔·골프·차량·투어 일정, 확인번호, 비용, 고객 입금, 공급처 지급, 환불, 변경·취소 사건이 연결될 수 있다.
- 목록 검색: 코드 원문, 손님, 거래처, 상태, 기간. 목록 행에는 출처/검토 필요 표시를 둔다. 검색 결과에 국가를 명시한다.
- 저장은 변경된 필드만 보내고 성공·실패·동시 수정 충돌을 구분한다. 충돌 시 사용자가 입력한 값은 유지하고 새 서버 값을 비교할 수 있게 한다.
- 취소·변경은 기록으로 남긴다. 원본 행과 과거 확인번호를 삭제해 현재값으로 덮어쓰지 않는다.

### 3.1 목록 조작

| 조작 | 입력 | 화면·데이터 결과 |
|---|---|---|
| 국가 전환 | PH/TH/JP | 해당 국가 예약만 요청. 해당 국가의 마지막 기간·필터 복원 |
| 월 이동 | 이전/다음 | 전월·현재·익월로 이루어진 3개월 창을 한 달 이동 |
| 검색 | 코드·손님·거래처 문자열 | 서버 검색으로 일치 예약 표시. 동일 코드의 여러 손님은 각각 표시 |
| 필터 | 상태·거래처 | 선택 국가와 3개월 범위 안의 목록 갱신 |
| 행 선택 | 예약 UUID | 해당 국가 상세 편집으로 이동. 행 안의 정산서 버튼은 별도 클릭 |
| 날짜 검토 | 날짜 미확정 보기 | 기본 기간에 놓을 수 없는 원본/예약 후보 표시 |

데스크톱 기본 목록은 엑셀형 표다. 2025 MAR 원장의 A:AC 업무 열 순서와 월 구획을 기준으로 총투어피·입금일자·비고/거래처·CODE·PAX·HOTEL·SC·항공·FIRST HOTEL·GUIDE·1TH~4TH·TRANS를 가로 배치한다. 시트별로 없는 필드는 빈칸과 출처 상태로 표시한다. 열 머리글·월 구획·고정 열·셀 메모 표시·원본 배경색을 살린다. 화면 폭보다 넓은 표는 수평 스크롤하고 CODE·손님은 찾기 쉽게 유지한다. **정산서 버튼은 모든 예약 행의 맨 오른쪽 마지막 열**에 배치하고 마지막 열까지 스크롤하면 접근할 수 있게 한다. 모바일은 같은 예약을 카드와 상세로 표시한다. 목록에서 직접 바꾸는 값은 최소화하고, 많은 열의 수정은 상세에서 출처·변경 이력을 보면서 한다. 목록의 상태는 텍스트로 보여주고 원본 색과 분리한다.

### 3.2 상세 저장

| 편집 대상 | 허용 동작 | 저장 확인 |
|---|---|---|
| 기본 정보 | 대표자·인원·확정된 날짜·거래처 연결 수정 | 이전값과 새 값, 수정 시각 기록 |
| 일정 | 호텔·골프·차량·투어 항목 추가/수정 | 한 날짜에 여러 서비스 허용 |
| 확인번호 | 호텔/골프/교통 번호 여러 개 추가·종류 검토 | 번호마다 출처 또는 수기 입력 표시 |
| 비용·결제 | 고객 입금/공급처 지급/환불 별도 입력 | 통화·금액·날짜·대상 거래를 확인 |
| 변경·취소 | 사건과 전후 값 기록 | 원본 예약과 메모 유지 |

저장 실패는 화면에 남기고, 다른 사용자가 먼저 수정한 충돌은 사용자 입력을 유지한 채 비교한다. 행 hover는 원본 배경색을 보존하면서 대비되는 반대색 테두리/반투명 강조를 주고 포인터가 벗어나면 원본색으로 돌아온다. 키보드 focus와 터치 선택도 같은 강조 상태를 제공한다. 행 클릭은 예약 상세 편집을 열며 행 안의 [정산서] 버튼은 행 클릭을 실행하지 않는다. 상세에는 서비스·비용 항목 추가/수정, 예약 [삭제]를 둔다. 삭제는 관리자 세션 확인 뒤 서버에서만 실행하고 삭제 전 예약 코드·손님을 다시 확인한다. 원본 셀·메모는 삭제하지 않으며 삭제 시각·대상·사유를 남기는 논리 삭제를 기본으로 한다.

### 3.3 신규 예약 코드 자동 추천과 수기 입력

현재 코드의 추천 형식을 재사용한다. Product Type, Base Date, Partner, PAX가 입력되면 상품 마스터의 prefix(없으면 product_code 대문자) + MMDD + '-' + partner_code + PAX + 호텔 접미어를 추천한다. 첫 호텔이 마스터에 매칭되면 poolvilla는 POOL, 그 외는 호텔 code 앞 세 글자를 접미어로 붙인다. 예: KGP, 9월 23일, TR, 4명, 호텔 없음 → KGP0923-TR4. 현재 화면처럼 [추천 코드 사용]으로 적용하거나 입력칸에 코드를 직접 쓸 수 있다. 수기값을 입력한 뒤 다른 필드를 바꿔도 자동으로 덮어쓰지 않는다. 신규 저장 시 서버가 코드 중복/형식 충돌을 검사하고 오류를 보여준다. 기존 엑셀에서 이관한 코드는 원문 그대로 보존하며 추천 규칙으로 재생성하지 않는다. 신규 예약에만 적용한다. 기존 추천은 날짜에 연도를 포함하지 않고 순번도 없으므로 같은 조건의 예약은 충돌할 수 있다. 중복 시 자동으로 임의 숫자를 붙이지 않고 사용자가 수기 코드를 고르거나 이후 확정된 규칙을 적용한다.

### 3개월 기본 범위

첫 진입은 필리핀이다. 현지 오늘이 속한 달의 첫날을 기준으로 전월 1일 이상, 다음다음 달 1일 미만을 조회한다. 예: 2026-11-13 접속 시 2026-10-01~2026-12-31. 월 이동은 3개월 창을 한 달씩 옮긴다. 예약 시작일 또는 해당 예약의 서비스일이 창에 들면 결과에 나타난다. 날짜를 확정하지 못한 행은 별도 '날짜 검토' 목록에서 찾을 수 있다. 전송을 여러 페이지로 나눠도 3개월 안의 대상 예약을 마지막 페이지까지 가져오거나 추가 로딩으로 접근 가능해야 한다.

### 국가별 범위

| 국가 | 첫 제공 업무 | 보류할 자동 규칙 |
|---|---|---|
| 필리핀 | 원장 예약, 호텔/골프/차량, 클락 거래처별 협력업체 바우처, PHP·KRW 시제, 신규 코드 추천·수기 입력 | 색 기반 상태·지급 판정, 마감·수익 배분 |
| 태국 | 독립 예약 목록·상세·수기 입력 틀, 별도 마스터 범위 | 원본과 태국 업무 규칙이 오기 전의 파서·가격·취소·정산 자동화 |
| 일본 | 수배 원장, 손님 명단, 객실·박수, 골프 티오프·추가 요금, 차량·기사, 취소·변경 | 일본 코드·요금·환율·상태 자동 해석 |

국가 선택은 예약의 주 운영 국가를 바꾸는 편집 기능이 아니다. 국가 안의 지점/지역은 별도 항목으로 둔다. 일본 자료와 기존 통합 원장의 같은 코드 행은 동일 예약 후보로 제시하되 자동 병합하거나 매출을 두 번 세지 않는다.

## 4. 클락 협력업체 바우처 폴더

KDS, Monkey(몽키), THE CLARK TOUR(더클락투어), CLARK GOGO(클락고고), GOLDEN RIVER(골든리버)를 거래처별 탭으로 둔다. 각 탭의 행은 거래처가 맡은 호텔·골프장 협력업체 수배/바우처 관리 기록이다. 거래처와 실제 호텔·골프장 공급처를 서로 다른 필드로 저장한다.

목록에는 원본의 접수/처리일 후보, 코드, 손님, 인원, 첫 서비스 날짜·내용, 금액/지급 문구 후보, 원본 행 색을 보여준다. 상세에는 날짜별 서비스, 골프장·호텔, 티오프/객실, 확인번호 여러 개, 메모 원문, 지급일·금액·통화 후보, 연결된 예약을 보여준다. 번호가 없는 행도 남긴다. 메모 속 PAID는 고객 입금인지 공급처 지급인지 확정 전에는 '미확정 문구'로 표시한다.

한 원본 행에 여러 날짜·서비스·번호가 있으면 항목을 여러 개로 나누고 각 출처 셀을 붙인다. Monkey와 THE CLARK TOUR의 앞부분 복사 행은 양쪽 원본 출처를 모두 남기고 별도 예약·바우처·금액으로 이중 집계하지 않는다. KDS의 열 밀림, CLARK GOGO의 금액/결제 문구, GOLDEN RIVER의 복수 번호는 검토 항목으로 보낸다.

| 거래처 탭 | 원본에서 특히 확인할 사례 | 화면 처리 |
|---|---|---|
| KDS | E3:F3 열 밀림, H3 메모, I3/J3 날짜·금액 혼합 | 열 위치만으로 코드·일차를 고정하지 않음 |
| Monkey | 같은 코드의 다른 고객, 비용 산식·인원 수정 메모 | 코드별로 손님·날짜·출처 구분 |
| THE CLARK TOUR | Monkey와 복사된 앞부분 행 | 두 탭 출처 유지, 중복 집계 금지 |
| CLARK GOGO | H4 결제일·금액 메모와 복수 확인번호 | 지급 주체·번호 유형 미확정 표시 |
| GOLDEN RIVER | 메모 한 개의 복수 번호/티오프 | 번호 여러 개와 원문 메모 함께 표시 |

## 5. 원본 이관과 검토

1. 원본 파일을 불변 배치로 등록하고 해시·파일명·시트 순서를 기록한다.
2. 값/수식 셀뿐 아니라 빈 셀의 메모와 배경색, 병합, 숨김, 조건부 서식을 보존한다. 수식 원문과 저장된 계산값을 구분한다. TODAY()는 실제 예약일로 해석하지 않는다.
3. 행 유형과 예약/수배/결제/취소 후보를 추출하고, 각 후보에 파일·시트·셀 좌표와 원문을 붙인다.
4. 같은 코드의 여러 손님, 중복 시트 행, 모호한 연도·통화·금액·PAID·색은 검토 목록에 둔다. 확정 전 자동 병합·자동 정산을 금지한다.
5. 파일별 재실행이 가능해야 한다. 중복 업로드와 실패한 부분 재처리를 구분하고, 운영자가 결정한 해석을 덮어쓰지 않는다.

최초 대조 기준은 두 파일 합계 10개 시트, 값/수식 셀 39,142개, 메모 3,436개다. 각 시트의 상세 수와 예외 좌표는 seed-data/ex.md를 따른다. 파일이 수정되면 이 수치는 새 파일에서 다시 계산한다.

## 6. 코드·색의 사용자 입력

seed-data/코드번호_확인질문.txt에 정리한 코드 문자 계열을 화면의 검토 목록으로 가져온다. 각 문자열 옆에 사용자가 '의미', '적용 국가/기간', '유효/오타/과거 표기', '메모'를 입력할 수 있게 한다. 입력 전에는 코드의 형태만 보여주고 의미를 임의로 확정하지 않는다. 원본 코드는 항상 그대로 보존한다.

원본색은 셀 단위로 재현한다. 초록/노랑/빨강/회색의 뜻도 시트·기간·행/셀별로 사용자가 설명할 수 있게 한다. 색은 현재 상태 배지와 분리한다. 색만으로 취소·지급·예약 확정을 실행하지 않는다.

## 7. 속도·모바일·오류

- 필리핀의 느린 회선을 기준으로 첫 화면은 3개월 요약을 빠르게 보여주고, 나머지 월/페이지를 점진 로딩한다. 한 페이지의 행 수를 제한해도 3개월 전체가 누락되어서는 안 된다.
- 상세 메모·원본 셀·긴 손님 명단은 상세 탭을 열 때 요청한다. 전체 파일을 브라우저로 다운로드하지 않는다.
- 필수 작업인 국가 전환, 예약 검색, 일정·바우처 확인, 메모 수정, 저장 결과 확인은 360px 화면에서 가능하다.
- 네트워크 실패 시 입력값을 유지하고 재시도한다. 저장 중·저장 완료·실패를 명시한다. 오래된 목록에는 마지막 갱신 시각을 표시한다.

## 8. 첫 범위에서 제외

복수 역할/회원가입, 7일 대시보드, 세부 가격 규칙·공휴일 자동 계산, 색만으로 상태 자동 전이, 날짜 경과에 따른 자동 마감, 가이드 수익 자동 배분, 전면 오프라인 편집, 국가 통화를 합친 단일 금액 합계, 별도 골프/호텔 리포트 화면. 신규 예약 코드 자동 추천과 수기 입력, 정산서 표는 첫 범위에 포함한다. 필요한 원본과 규칙이 확인되면 제외한 기능을 별도 단계에서 추가한다.

## 9. 정산서 표와 예약별 모달

- 메인 예약 표의 각 행 맨 뒤, 모든 업무 열 다음 마지막 열에 '정산서' 버튼을 둔다. 버튼은 그 예약 UUID의 정산서 모달을 연다. 예약 코드가 중복되어도 다른 예약 정산서를 열지 않는다.
- DW Tour 메뉴바에 '정산서'를 별도 1차 메뉴로 둔다. 전체/국가별, 기간, 코드·손님·거래처를 검색하는 정산 표를 보여주고 행 선택 시 같은 모달을 연다.
- 기존 엑셀 2025 MAR의 AD:AQ 정산 영역을 첫 화면 열 순서의 기준으로 사용한다: CODE, 총 투어피, 페소, Hotel, 1TH, 2TH, 3TH, 4TH, 현지행사비, 그 외 지출, 옵션, 수익. AP/AQ는 원본 머리글이 비어 있어 '원본 AP', '원본 AQ'로 표시하고 뜻을 사용자 확인 항목으로 남긴다.
- 원본 AO 열에는 AF−AG−AH−AI−AJ−AK−AL−AM+AN 수식이 반복되고 AP 열에는 AO/AQ 수식이 있다. AE2에는 22.5가 있고 AF의 일부 행은 AE/AE2로 계산하며, AQ에는 61.5 등 여러 값이 있다. 이 수식을 원본 보기에서 그대로 보여준다. 새 정산 계산에 쓸 통화·환율·차감/가산 규칙은 사용자 확인 뒤 버전을 정해 적용한다.
- 모달에는 원본 정산 행의 값·수식·저장 계산값과 구조화된 비용/입금/지급 내역을 나란히 표시한다. 원본 1TH~4TH 밖의 서비스 비용과 복수 호텔·골프 비용은 추가 항목으로 표시해 누락하지 않는다. 수익 숫자를 계산할 근거가 부족하면 빈값/검토 상태로 표시한다.
- 정산서 목록에서 같은 예약이 여러 서비스일에 나타나더라도 정산 행은 예약 UUID 기준 한 번만 집계한다. 복사된 거래처 탭의 바우처 금액도 검토 없이 두 번 반영하지 않는다. 통화가 다른 금액은 환율 근거 없이 합산하지 않는다.

## 10. 기능별 인수 확인

### 공통 헤더 환율

- 필리핀·태국·일본·정산서 등 접속 가능한 모든 화면의 DW Tour 헤더에 네이버 환율 세 개를 표시한다: 1 USD = ? KRW, 1 PHP = ? KRW, 100 JPY = ? KRW. 일본 단위 100엔을 생략하지 않는다.
- 기준은 네이버에 표시된 원화 매매기준율/고시값이다. 출처 링크, 네이버 고시 시각과 앱의 마지막 조회 시각을 별도로 보여준다. 매일 **06:00 Asia/Seoul**에 서버가 세 통화를 한 번 확인한다. 주말·휴일 또는 아직 새 고시가 없으면 이전 고시값을 '이전 고시'와 시각을 붙여 표시한다. 오늘 6시에 확인했다는 이유로 '오늘 환율'이라고 쓰지 않는다.
- [환율 새로고침]은 일반 사용자 클릭 시 서버에서 다시 조회한다. 완료 전에는 진행 표시, 성공 시 값·고시 시각·조회 시각 갱신, 실패 시 직전 정상값과 실패 안내를 표시한다. 버튼 연타는 중복 요청으로 합치거나 짧게 제한한다. 웹 브라우저는 네이버에 직접 요청하지 않고 서버가 검증한 결과만 읽는다.
- 이 헤더 환율은 정보 표시용이다. 원장 AD:AQ의 기존 환산식, 예약 비용, 정산서 금액을 자동 재계산하거나 덮지 않는다.
