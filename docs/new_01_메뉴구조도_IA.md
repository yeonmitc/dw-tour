# 01. 새 메뉴 구조와 정보 구조

작성 기준: 2026-11-13. 이 문서는 구현할 웹앱의 목표 구조다. 기존 01~05는 현재 코드 설명이며, 새 01~05와 06_엑셀기반_통합여행운영_개발계획.md가 새 시스템의 기준이다. 앱 코드는 이 문서 작성 단계에서 수정하지 않는다.

## 1. 제품 구조

하나의 웹앱과 하나의 새 Supabase 프로젝트에서 필리핀(PH), 태국(TH), 일본(JP)의 예약을 관리한다. 화면의 탐색·검색·저장 규칙은 공통이다. 예약, 수배, 결제, 취소의 업무 규칙과 입력 항목은 국가별로 나눈다. 한 예약의 주 운영 국가는 하나이며 지점은 그 국가 안의 하위 분류다.

첫 접속은 로그인 없이 바로 **필리핀 예약**으로 이동한다. 관리자 전용 동작을 선택했는데 관리자 세션이 없을 때만 비밀번호 모달을 띄우고, 인증 뒤 원래 동작을 이어간다. 일반 예약 조회·추가·수정에는 관리자 로그인이 필요 없다. 예약 목록의 기본 기간은 현지 오늘이 속한 달의 이전 달·현재 달·다음 달이다. 예를 들어 오늘이 2026-11-13이면 2026-10-01 이상, 2027-01-01 미만의 3개월을 표시한다. 월 이동 버튼은 이 창을 한 달씩 옮긴다. 필터를 바꾼 뒤에는 국가별 마지막 조회 기간과 필터를 화면 세션 안에서 유지한다.

메인 예약 화면의 데스크톱 기본 보기는 NEW 2026.xlsx의 2025 MAR 원장처럼 가로로 넓은 행·열 표다. 파란 열 머리글, 월 구획, 예약 한 줄, 날짜별 1TH~4TH 묶음, 원본 배경색·메모 표시를 최대한 익숙하게 재현한다. 표의 열·색·셀 내용은 원본 출처와 연결한다. 행 hover는 원본색을 덮지 않는 반대색 강조를 보여준다. 행 클릭은 해당 예약의 상세 편집 화면을 열고, 추가·수정은 바로 사용하며 삭제만 관리자 세션을 요구한다. 웹에서 필요한 '정산서' 버튼은 예약 행의 **맨 오른쪽 마지막 열**에 두고 검색·저장 상태를 추가한다. 모바일은 같은 예약을 카드/상세로 읽게 하여 좁은 화면에서도 확인할 수 있게 한다.

DW Tour 공통 헤더에는 네이버 원화 기준 USD·PHP·JPY 환율과 고시 시각, 마지막 확인 시각, [환율 새로고침]을 둔다. 매일 한국시간 오전 6시 자동 확인을 기본으로 하며 버튼으로 즉시 다시 확인할 수 있다. 정확한 값은 서버에서 조회한 스냅샷만 보여주고 예약·정산 계산에는 자동 반영하지 않는다.

## 2. 탐색 계층

| 1차 메뉴 | 2차 화면 | 첫 범위 |
|---|---|---|
| 필리핀 예약 | 3개월 예약 목록·달력, 예약 상세·신규 | 필수 |
| 필리핀 예약 > 클락 협력업체 바우처 | KDS, 몽키, 더클락투어, 클락고고, 골든리버 거래처 탭 | 필수 |
| 필리핀 예약 > 시제 | PHP·KRW 장부 | 필수 |
| 태국 예약 | 독립 예약 목록·상세·신규 틀 | 필수 틀, 원본·규칙 대기 |
| 일본 예약 | 예약 목록·상세, 수배 명단·호텔·골프·차량 | 필수 |
| 정산서 | 전체 예약 정산 표, 국가·기간 검색, 예약별 정산 모달 진입 | 필수 |
| 전체 검색 | 국가 간 코드·손님·거래처 검색 | 필수, 조회 중심 |
| 원본·검토 | 파일/시트/행/셀 보기, 모호한 데이터 검토 | 필수 |
| 기본 설정 | 거래처, 골프장, 호텔 등 확인된 마스터 | 필수 최소 범위 |

클락 바우처의 다섯 탭 이름은 **주요 거래처**다. 그 안에 적힌 골프장·호텔은 실제 서비스를 제공하는 **협력업체**다. 거래처 탭을 다섯 개의 별도 데이터베이스나 다섯 개의 완전히 다른 바우처 기능으로 만들지 않는다. 동일한 바우처 화면에서 원본 시트 탭을 바꾼다. 행의 거래처 연결이 아직 미확정이어도 해당 원본 탭에서 조회할 수 있다. 원본 시트명과 셀 위치는 상세에서 확인한다.

데스크톱은 국가 메뉴와 하위 메뉴를 왼쪽에 표시한다. 모바일은 상단 메뉴 버튼으로 같은 메뉴를 열고, 클락의 다섯 거래처는 화면 안의 선택 목록으로 제공한다. 모바일에서 메뉴가 숨겨져 접근할 수 없는 상태를 만들지 않는다.

## 3. 라우트 계약

아래 경로는 새 화면 설계의 목표이며 현재 코드에 이미 존재한다는 뜻은 아니다.

| 경로 | 화면 | 접근 |
|---|---|---|
| / | /ph/reservations로 이동 | 바로 접속 |
| /ph/reservations | 필리핀 3개월 예약 | 바로 조회 |
| /ph/reservations/new, /ph/reservations/:id | 필리핀 예약 추가·상세·수정 | 바로 사용, 삭제만 관리자 |
| /ph/clark/vouchers | 클락 거래처별 바우처 폴더 | 바로 조회·일반 수정 |
| /ph/clark/vouchers/:entryId | 원본 업무 행과 날짜별 수배/바우처 항목 | 바로 조회·일반 수정 |
| /ph/cash | 필리핀 PHP·KRW 시제 | 바로 조회 |
| /th/reservations, /th/reservations/new, /th/reservations/:id | 태국 예약 공간 | 바로 사용, 삭제만 관리자 |
| /jp/reservations, /jp/reservations/new, /jp/reservations/:id | 일본 예약·수배 공간 | 바로 사용, 삭제만 관리자 |
| /settlements | 전체 정산서 표 | 바로 조회 |
| /search | 전체 검색 | 바로 조회 |
| /sources, /sources/:batchId | 원본 파일과 검토 목록 | 조회는 바로, 검토 확정은 관리자 |
| /settings | 최소 마스터 설정 | 조회는 바로, 설정 변경은 관리자 |

각 상세 경로의 :id는 내부 UUID다. 코드 문자열을 경로의 고유 식별자로 사용하지 않는다. 상세의 국가와 예약의 실제 국가가 다르면 올바른 국가 경로로 이동하거나 오류를 표시한다. 태국 원본이 없더라도 예약 공간은 독립 메뉴로 둔다. 실제 업무 입력의 필수 항목과 자동 규칙은 태국 자료를 받은 뒤 확정한다.

### 3.1 라우트 트리

~~~text
DW Tour
├─ 관리자 권한 요청 시 모달          비밀번호 입력 후 원래 동작 계속
└─ /                                필리핀 예약으로 이동
   ├─ /ph/reservations              필리핀 예약 목록
   │  ├─ /new                        필리핀 예약 생성
   │  └─ /:id                        필리핀 예약 상세
   ├─ /ph/clark/vouchers            클락 협력업체 바우처
   │  └─ /:entryId                   거래처 탭 원본 업무 행 상세
   ├─ /ph/cash                      필리핀 시제
   ├─ /th/reservations              태국 예약 목록·생성·상세
   ├─ /jp/reservations              일본 예약 목록·생성·상세
   ├─ /settlements                  국가별/전체 정산서 표
   ├─ /search                       전체 검색
   ├─ /sources                      원본·검토
   └─ /settings                     최소 마스터 설정
~~~

화면 진입 때 관리자 세션을 강제하지 않는다. 삭제·원본 이관·관리 설정 변경처럼 관리자 권한이 필요한 동작에서만 비밀번호 모달을 열고 서버에서도 권한을 확인한다. 국가 코드가 없는 /bookings 단일 경로는 새 예약 시스템의 기본 경로로 쓰지 않는다. 필요한 경우 기존 링크를 새 국가 경로로 연결하는 전환 처리를 둔다.

## 4. 화면 간 이동

1. 주소 접속 → 로그인 없이 필리핀 예약의 3개월 창.
2. 국가 전환 → 해당 국가 예약 목록. 그 국가에서 마지막으로 본 기간·필터를 사용하며 처음이면 현재 기준 3개월.
3. 예약 행/카드 → 해당 국가 예약 상세. 추가·수정은 바로 사용하고, 삭제만 관리자 비밀번호를 확인한다. 바우처, 결제, 원본 출처로 이동 가능.
4. 예약 행 맨 오른쪽 마지막 열의 정산서 버튼 → 해당 예약의 정산 모달. 정산서 메뉴 → 전체 정산 표 → 행 선택 시 같은 모달.
5. 클락 거래처 탭 → 바우처 업무 행 → 연결된 예약과 호텔/골프 서비스. 연결이 미확정이면 원본과 검토 상태를 표시.
6. 전체 검색 → 결과의 국가를 표시 → 그 국가 예약 상세.
7. 원본·검토 → 원본 셀/메모/색 → 구조화 후보와 연결 근거. 원본 수정 없이 해석만 확정.

## 5. 기존 코드의 재사용 범위

React 19/Vite, React Router, Supabase JS, TanStack Query, react-hook-form의 기본 구조를 활용할 수 있다. 현재 예약 목록·상세, 바우처, 설정 화면은 화면 구성과 입력 흐름의 참고 자료다. 실제 코드 수정 단계에서 컴포넌트별 재사용 가능 여부를 확인한다. 기존 Supabase DB는 문제가 있으므로 새 DB로 다시 만들고, 이전 스키마를 그대로 복제하지 않는다.

기존 대시보드의 7일 메트릭, 골프/호텔 별도 리포트, 복수 사용자 역할, 지점별 계정, 전체 Query의 24시간 영구 캐시, 상태 자동 생성, 가격 규칙·공휴일 자동 계산은 첫 메뉴에서 제외한다. 신규 예약의 코드 자동 추천·수기 입력은 첫 범위에 포함한다. 새 시스템의 첫 화면은 대시보드가 아니라 예약이다.

### 5.1 목표 폴더 구조

아래는 개발할 때의 모듈 분리 예시다. 실제 코드 파일은 아직 만들지 않았다.

~~~text
src/
  app/                    라우팅·공통 레이아웃
  common/                 표·카드·메모·색·오류·모바일 메뉴
  features/
    auth/                 관리자 세션
    reservations/         공통 예약 목록·상세·편집
    markets/ph/           필리핀 화면 구성·시제
    markets/th/           태국 화면 구성, 규칙 확정 전 틀
    markets/jp/           일본 수배 화면 구성
    vouchers/clark/       거래처별 탭·협력업체 바우처
    settlements/          전체 정산 표·예약별 정산 모달
    sources/              원본 보기·검토·코드/색 뜻
    masters/              거래처·호텔·골프장
  lib/                    Supabase 클라이언트·공통 데이터 접근
supabase/
  migrations/             새 DB 스키마·RLS·조회 함수
seed-data/                원본 엑셀·분석 문서
docs/                     새 01~05와 개발 계획
~~~

공통 예약 컴포넌트와 국가별 규칙/표시 구성을 나눈다. 태국 자료가 오기 전에는 태국 파서나 정산 규칙을 만들지 않는다. 현재 src의 실제 파일 배치는 구현 시 재사용 가능성을 판단해 점진적으로 옮긴다.

### 5.2 데이터 흐름

~~~text
엑셀 원본 → 관리용 가져오기 → 새 Supabase 원본 보존층
                                ↓ 검토·확정
                        예약·일정·결제 운영층
                                ↓ RLS를 따르는 조회
바로 접속 → 공통 레이아웃 → 국가별 예약 화면 → 목록 요약/필요한 상세
                                ↓
                     클락 바우처·일본 수배·필리핀 시제
~~~

React Query는 서버 데이터의 짧은 캐시, 폼 상태는 입력값 유지, 앱 상태는 국가/기간/필터에 쓴다. 손님 명단·메모·정산 정보를 24시간 기기 저장소에 남기는 기존 방식은 새 시스템 기본값으로 사용하지 않는다.

실제 이관 순서는 새 Supabase 연결·스키마·일반/관리자 권한과 신규 예약 코드 추천/수기 저장 검증 → 두 엑셀의 원본 배치 적재 → 시트별 셀·메모·색·예약 수 대조 → 운영 화면 공개다. 신규 예약에만 현재 코드 추천을 쓰고 이관된 코드에는 적용하지 않는다.
