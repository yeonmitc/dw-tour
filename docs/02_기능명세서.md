# 02 — 기능 명세서

> DW Tour (travel-ops-frontend) 소스 코드에 구현된 모든 기능의 상세 명세

## 1. 인증 (Authentication)

### 1.1 로그인

- **위치**: `src/pages/LoginPage.jsx`, `src/features/auth/authApi.js`
- **입력**: 이메일, 비밀번호
- **흐름**:
  1. 사용자가 이메일/비밀번호 입력
  2. `supabase.auth.signInWithPassword()` 호출
  3. 성공 시 → `profiles` 테이블에서 사용자 프로필 조회 (`role`, `branch`)
  4. `authStore`에 session + user + profile 저장 (Zustand persist → localStorage)
  5. `/` (대시보드)로 리다이렉트
- **예외 처리**:
  - 인증 실패 시 에러 메시지 표시
  - 프로필 조회 실패 시에도 기본 정보로 진행

### 1.2 세션 복구 (Auth Bootstrap)

- **위치**: `src/features/auth/useAuthBootstrap.js`
- **동작**: 앱 시작 시 `main.jsx`의 `Bootstrap` 컴포넌트에서 실행
  1. `supabase.auth.getSession()`으로 기존 세션 확인
  2. 세션 존재 시 → `authStore`에 복구
  3. `supabase.auth.onAuthStateChange()` 리스너 등록 → SIGNED_IN/SIGNED_OUT 이벤트 처리
  4. SIGNED_OUT 발생 시 → authStore 초기화 + `/login`으로 이동

### 1.3 로그아웃

- **위치**: `src/common/components/Layout.jsx` (사이드바 하단)
- **동작**: `signOut()` → authStore 초기화 → `/login` 리다이렉트

### 1.4 브랜치 필터링 (권한 기반)

- **위치**: `src/features/auth/useBranchFilter.js`
- **규칙**:
  - `master_office` 역할 → 모든 브랜치(ALL) 접근 가능
  - `office` 역할 → 본인 소속 브랜치만 필터링 (useBranchFilter에서 branch 목록 제한)

## 3. 예약 목록 (Bookings List)

- **위치**: `src/pages/BookingsPage.jsx` (1,656행)
- **데이터 소스**: `booking_dashboard_view` (Supabase 뷰)

### 3.1 뷰 모드

| 모드 | 설명 |
|---|---|
| Grid View | 테이블 형태의 예약 목록 (기본) |
| Calendar View | 월별 캘린더에 예약을 날짜별로 표시 |

### 3.2 필터링

| 필터 | 구현 |
|---|---|
| 브랜치 | `uiStore.branch` 연동 (ALL/Philippines/Chiang Mai/Fukuoka) |
| 상태 | 드롭다운 (ALL/NEW/REQUESTED/CONFIRMED 등) |
| 결제 상태 | 드롭다운 (ALL/UNPAID/PARTIAL/PAID) |
| 호텔 결제 | ALL/PAID/UNPAID |
| 키워드 검색 | customer_name, code, partner_code에 ILIKE 검색 |
| 날짜 범위 | 월 네비게이션 (←/→) 또는 직접 선택 |

### 3.3 인라인 편집

- 그리드 뷰의 특정 필드를 직접 클릭하여 편집 가능
- 편집 필드: 상태(status), 메모(memo), 호텔 결제(hotel_paid), 골프 상태(golf_status) 등
- 편집 시 `updateBooking()` API 호출
- 메모 편집은 Popover 컴포넌트로 확장 UI 제공

### 3.4 날짜별 결제 토글

- 각 날짜 행에서 결제 상태를 토글로 변경 가능
- 낙관적 동시성 제어 (`updated_at` guard) 적용

### 3.5 월 네비게이션

- `←` / `→` 버튼으로 이전/다음 월 이동
- 현재 월 표시 (YYYY년 MM월)

### 3.6 자동 마감

- 특정 조건(날짜 경과 + 결제 완료) 충족 시 예약 상태가 자동으로 CLOSED 전이

## 4. 예약 상세 (Booking Detail)

- **위치**: `src/pages/BookingDetailPage.jsx` (2,109행)
- **폼 라이브러리**: react-hook-form v7

### 4.1 신규 생성 vs 수정

| 모드 | 경로 | 동작 |
|---|---|---|
| 신규 | `/bookings/new` | 빈 폼 + 기본값으로 시작 |
| 수정 | `/bookings/:uuid` | `getBooking(id)`로 기존 데이터 로드 |

### 4.2 예약 코드 생성 (BookingCodeSection)

- **위치**: `src/features/bookings/BookingCodeSection.jsx`, `src/utils/codePreview.js`
- **필수 입력**: Product Type + Partner + Base Date
- **자동 생성 로직**: `{product_code}{YYMMDD}-{partner_code}{sequence}`
- **PRODUCT_MAPPING**: 상품 유형별 접두사 매핑
- 추천 코드(suggestedCode) UI 제공 → "Use" 버튼으로 적용

### 4.3 고객 정보 (CustomerNameFields)

- **위치**: `src/common/components/CustomerNameFields.jsx`
- **한→영 자동 변환**: `koreanToEnglishName()` (src/utils/koreanName.js)
  - 성(last name): 김→Kim, 이→Lee, 박→Park 등 특수 매핑
  - 이름(first name): 초성+중성+종성 로마자 변환 테이블
- 레이아웃 모드: `booking` (전체 폼) | `voucher` (간소화)

### 4.4 일정 관리 (Schedule)

- 날짜별 서비스 항목 생성/관리:
  - 골프 (golf_name, tee_time, pax)
  - 호텔 (hotel_name, room_type, check_in/out)
  - 차량 (vehicle_type, route)
- `booking_day_items_mb` 테이블에 upsert
- 공유 키: `(booking_id, service_date, slot_no)`
- 공휴일 경고: `holidays` 테이블과 비교하여 공휴일 표시

### 4.5 상태 자동화

| 조건 | 다음 상태 |
|---|---|
| 날짜 경과 + 결제 완료 | → CLOSED |
| 티타임 변경 (>>) | → REQUESTED |
| 결제 완료 (NEW 상태에서) | → DEPOSIT |
| 수동 변경 불가 상태 | CANCLE, CLOSED → 수동 변경 불가 |

### 4.6 마스터 데이터 연동

- 가이드: `guide_master` 테이블 → 지점별 필터링
- 기사: `driver_master` 테이블 → 지점별 필터링
- 차량: `vehicle_master` 테이블 → 지점별 필터링
- 파트너: `partners` 테이블 → 코드/라벨 매핑
- 상품 유형: `product_types` 테이블 → 코드/라벨/지역 매핑

### 4.7 예외 처리

- **낙관적 동시성 충돌**: `updateBookingWithGuard()` — `updated_at` 비교, 충돌 시 `CONFLICT` 에러 throw + 사용자에게 새로고침 안내
- **필수 필드 검증**: react-hook-form `required` + 에러 메시지 표시
- **지역 잠금 (regionLocked)**: office 사용자는 본인 지점의 상품/파트너만 선택 가능

## 5. 바우처 관리 (Vouchers)

### 5.1 바우처 목록

- **위치**: `src/pages/VouchersPage.jsx` (443행)
- **데이터 소스**: `vouchers` 테이블 + `bookings` 테이블 수동 조인
- **필터링**: 브랜치, 상태, 날짜 범위, 키워드(partner_name ILIKE)
- **인라인 편집**: 상태, 결제 상태, 금액 등

### 5.2 바우처 생성/수정 모달 (VoucherModal)

- **위치**: `src/features/vouchers/VoucherModal.jsx` (938행)
- **폼 라이브러리**: react-hook-form v7
- **기본값**: Product=GONLY, Partner=Monkey Travel, Currency=PHP, Pax=4
- **골프 스케줄 입력**:
  - 날짜, 티타임, 골프장 선택(direct input 또는 select), 바우처 코드
  - Philippines 골프장 목록 필터링 (country/region 기준)
- **바우처 코드 자동 생성**:
  - 형식: `GONLY{MMDD}-MK{pax}{courseCode}`
  - 추천 코드 UI + "Use" 버튼
- **스케줄 텍스트 자동 빌드**:
  - 포맷: `{MM/DD} {course} {HH:MM} {extras}`
  - 수동 편집 시 자동 빌드 비활성 (manualFlag)
- **상태 자동화** (VoucherModal 내부):
  - 날짜 경과 + 결제 완료 → CLOSED
  - `>>` 포함 스케줄 → REQUESTED
  - 결제 완료 + NEW → DEPOSIT
  - CANCLE/CLOSED → 자동 전이 방지
- **Change Tee Time**: 체크박스 → 상태를 REQUESTED로 전이 + 스케줄 텍스트에 `>>` 추가

## 8. 공급자 관리 (Suppliers)

| 함수 | 테이블 | 설명 |

## 9. 전역 기능

### 9.1 브랜치 필터 (Topbar)

- **위치**: `src/common/components/Topbar.jsx`, `src/store/uiStore.js`
- **옵션**: ALL / Philippines / Chiang Mai / Fukuoka
- **동작**: 선택 시 `uiStore.branch` 변경 → 모든 React Query가 자동으로 새 파라미터로 리페치

### 9.2 키워드 검색 (Topbar)

- **위치**: `src/common/components/Topbar.jsx`, `src/store/uiStore.js`
- **동작**: 입력 시 `uiStore.keyword` 변경 → 디바운스 후 예약/바우처 목록 리페치
- **검색 대상**: customer_name, code, partner_code (ILIKE)

### 9.3 캐시 영속화 (Cache Persist)

- **위치**: `src/providers/QueryProvider.jsx`
- **구현**: `@tanstack/query-persist-client-core` + `localforage` (IndexedDB)
- **설정**: maxAge = 24시간, localforage 키 = `dw-tour-query-cache`
- **목적**: 느린 인터넷 환경에서 재접속 시 즉시 UI 표시

### 9.4 동기화 상태 표시

- Topbar에서 React Query의 `isFetching` 상태를 표시
- 데이터 동기화 진행 중임을 사용자에게 시각적으로 알림

### 9.5 한글→영문 이름 변환

- **위치**: `src/utils/koreanName.js`
- **용도**: 고객 한글명 입력 시 영문 이름 자동 생성
- **특수 처리**: 성(姓) 매핑 테이블 (김→Kim, 이→Lee, 박→Park 등 20+ 성)
- **일반 변환**: 초성/중성/종성 → 로마자 매핑 테이블 사용

### 9.6 낙관적 동시성 제어

- **적용 대상**: 예약(`bookings`), 바우처(`vouchers`)
- **구현**: `updated_at` 컬럼 비교 → 불일치 시 `CONFLICT` 에러
- **UX**: 에러 발생 시 사용자에게 "새로고침 후 재시도" 안내
