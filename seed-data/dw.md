# DW 투어 웹앱 데이터 설계 (1차)

NEW 2026.xlsx의 8개 시트와 일본 수배.xlsx의 2개 시트, 합계 39,142개 값/수식 셀·3,436개 셀 메모 및 배경색을 조사한 초안이다. 근거와 예외는 ex.md 참조. 필리핀·태국·일본은 각각 별도 운영 규칙을 가진다. 현재 태국 전용 원본은 없다. 이 단계에서는 기존 웹 코드와 독립적으로 데이터 누락 없는 이관 구조를 정의한다. 아래 테이블과 기능은 구현 제안이며, 엑셀만으로 확정할 수 없는 영업 규칙은 별도로 표기한다.

## 1. 핵심 원칙

1. 원본 보존 후 구조화: 가져오기 배치, 시트, 행, 셀 주소, 원본 값/수식, 계산 캐시, 메모 원문·작성자, 채우기 색을 저장한다. 파싱이 틀려도 원본에서 다시 생성한다.
2. 예약 코드 비유일: 같은 코드가 여러 손님/행/기간에 쓰인다. 내부 reservation_id를 PK로 사용하고 booking_code는 검색용이다. 전역 UNIQUE 금지.
3. 한 예약에 여러 일정·공급처·확인번호·비용·결제: 호텔 2객실/서로 다른 박수, 골프장 여러 티오프, 선금·잔금·환불을 별도 행으로 표현한다.
4. 사실과 추정 구분: 메모의 PAID, 날짜, 수식, 금액은 우선 후보로 적재한다. 대상 거래·통화·연도가 모호하면 needs_review를 유지한다. 빈 메모를 미납으로 바꾸지 않는다.
5. 화면은 통합, 출처는 유지: 예약 화면에서 원장·거래처 시트 정보를 함께 보여주되 각 값의 출처 셀, 원본 색, 검토/수정 이력을 조회할 수 있게 한다.
6. 클락의 KDS·Monkey·THE CLARK TOUR·CLARK GOGO·GOLDEN RIVER는 주요 거래처별 골프장·호텔 협력업체 바우처 탭이다. 거래처와 실제 서비스 공급처를 별도 주체로 모델링하고, 이 탭의 행을 원장 예약과 연결한다.

- import_batches 1:N source_rows 1:N source_cells
- source_rows N:M reservations (reservation_sources 연결 테이블)
- agencies 1:N reservations
- reservations 1:N guests, itinerary_items, cost_lines, payment_transactions, reservation_events
- itinerary_items 1:N service_confirmations, cost_lines, payment_transactions

업무 테이블에 created_at, updated_at과 필요 시 created_by를 둔다. 변경은 감사 로그로 기록한다. 금액은 정밀 numeric과 ISO 통화 코드(PHP, KRW)를 사용한다. 서로 다른 통화를 환율 근거 없이 합산하지 않는다. 고객/공급처 결제의 현금 흐름과 원가·수익 계산은 구분한다.

## 4. 배경색 처리

- 배경색은 데이터의 일부다. 셀의 fill pattern과 RGB/테마/인덱스/tint를 원본 좌표에 연결한다. 테마색은 RGB로 임의 치환하지 않고 원본 테마 정보도 보존한다. 빈 셀을 포함한 연속 색 구간, 병합 셀, 조건부 서식 규칙도 적재 대상이다.
- 2025 MAR의 값/메모 있는 셀에 31가지 색 표현, 색칠된 빈 셀 약 55,088개가 있다. 색이 행 전체인지 특정 서비스 셀만의 강조인지 구분해야 한다. 원본 보기에서는 행과 셀의 색을 재현한다.
- 빨강, 노랑, 초록, 회색 등은 예약 상태나 결제 상태의 후보 신호로만 사용한다. 동일 색이 다른 맥락에 등장한다. 시트·기간별 색 범례를 실제 사례와 대조해 사용자에게 확인받기 전에는 색만으로 확정/취소/지급 판정 또는 정산 제외를 하지 않는다.
- 파서 결과에는 source_color와 inferred_color_label을 분리한다. 색 규칙이 확정되면 버전을 부여하고 재분석할 수 있게 한다. 색과 텍스트/메모가 충돌하면 review_issues를 만든다.

## 5. 이관 파이프라인

1. 원본 적재: 파일 해시 기록 → 모든 시트를 순서대로 읽고 행·셀·수식·메모·색·병합 정보를 저장. 빈 셀의 메모/색도 포함. 원본 파일은 변경하지 않는다.
2. 행 분류: 시트별 헤더/월 구획/실제 예약/미완성 입력/수식 템플릿/취소 이력을 분류. 월 구획만으로 연도를 결정하지 않는다.
3. 후보 파싱: 날짜, 코드, PAX, 장소, 티오프, 객실수·박수, 확인번호, 비용 산식, BOOKED/FINAL/PAID/REVISED/CANCELLED 이벤트를 독립 추출. 4,000×1RM×4N과 5,000×4PAX를 같은 수량 모델로 강제하지 않는다. 메모 하나에서 여러 결과가 나올 수 있다.
4. 예약 연결: 코드 일치에 더해 행사 날짜, 대표자, PAX, 거래처, 일정 근거를 비교해 후보 제시. 같은 코드/다른 손님, 서로 다른 시트의 복사 행, 기간 재사용을 자동 병합하지 않는다. 내부 UUID 생성.
5. 검토 후 확정: 모호한 연도, 결제 주체, 통화, 복수 금액, 동일 코드, 상충하는 일정/상태/배경색을 검토 큐에 보낸다. 확정한 필드만 운영 계산·알림에 사용한다.
6. 검증·재실행: 시트별 값 셀·메모·색 구간 수를 대조. 원본 좌표 링크, 파서 버전별 결과 비교, 중복 업로드 방지, 부분 실패 시 재개. 수식의 저장 캐시를 같이 읽되 캐시 부재를 0으로 처리하지 않는다.

### 수용 기준

- NEW 2026.xlsx의 8개 시트에서 원본 행·셀·메모·배경색을 조회할 수 있다. 1차 값/수식 셀 32,783개, 메모 2,828개. 일본 수배.xlsx의 2개 시트는 값/수식 셀 6,359개, 메모 608개에 더해 숨김 행·조건부 서식도 보존한다. 파일 변경 시 기준치 재계산.
- 표본 검증: 2025 MAR K11의 두 객실 확인번호/비용, O10 복수 바우처, U9 변경 이력, CLARK GOGO H4 결제일/금액, GOLDEN RIVER H9 복수 번호, 취소 K1 객실별 번호, KDS E3:F3 열 밀림. 취소 1~4행 및 Monkey C39 등의 배경색도 원본과 일치.
- 같은 코드 행을 분실하거나 임의 병합하지 않는다. Monkey/THE CLARK TOUR의 복사 행을 이중 집계하지 않는다.
- 클락 5개 거래처 탭의 바우처 업무 행은 모두 남기고, 예약·공급처·확인번호 연결만 근거에 따라 확정한다. 거래처별 행 수, 원본 메모·색 수, 중복 후보 수를 따로 대조한다.
- 파싱 실패 항목은 unknown/검토 상태로 남는다. 빈 날짜·금액을 0이나 오늘 날짜로 바꾸지 않는다. 색의 뜻을 확인하기 전에는 색만으로 업무 상태가 바뀌지 않는다.

## 6. 화면·업무 순서

1. 원본 검토 화면: 시트/행/셀 검색, 원본 값·메모·배경색과 파싱 결과, 검토 상태를 비교.
2. 예약 목록·상세: 거래처/행사일/코드/손님 검색, 출처 표시, 일정·가이드·호텔/골프·확인번호·비용·결제 연결. 동일 코드 여러 예약 구분.
3. 클락 협력업체 바우처 폴더: KDS·몽키·더클락투어·클락고고·골든리버 거래처 탭을 둔다. 각 탭에서 골프장/호텔, 서비스 날짜, 코드·손님·인원, 확인번호, 결제일·금액 후보, 메모·원본색, 원장 예약 연결을 조회·수정한다. 데스크톱은 빠른 표, 모바일은 거래처 선택과 바우처 카드·상세를 사용한다. 공급처별 검색은 별도 필터로 둔다.
4. 일정·티오프 캘린더: 확정된 서비스 날짜/시각 표시. REQ는 요청 상태, 변경 전 시간은 이력으로 유지. 일정 클릭 시 바우처·결제 기록.
5. 입금/지급·시제: 고객 입금과 공급처 지급 분리, 부분 결제/잔금/환불, 통화별 시제. 미지급 경고는 지급 의무와 기한이 확인된 건에만 표시.
6. 취소·변경/감사: 변경 전후와 사유, 원본 메모를 추적. 예약 삭제 대신 상태/이벤트 기록.
7. 정산: 확인된 수입·원가·결제 구분, 환율·미확정 항목 노출. 월별 집계 기준일(예약일/행사일/입금일) 선택.

## 7. 기존 초안에서 보류할 규칙

- 가이드 배분 5:5 / 8:2 / 7:3 / 6:4: 이전 문서의 제안이지만 엑셀 셀·수식에서 적용 범위, 원화/페소 기준, 비용 제외 범위, 1명 사례를 검증하지 못했다. commission_rules에 효력 기간·상품·가이드피 여부·PAX 구간·통화/반올림 방식을 버전 관리할 수 있게 하되 운영 자동 정산 적용 전 업무 확인이 필요하다.
- 매월 잔액 자동 이월: 시제 시트는 여러 달을 포함하고 날짜/잔액 빈 행이 많다. 거래 순서와 시작 잔액 확정 후 월 마감/이월 구현.
- 메모 첫 줄=바우처, PAID=전체 결제 상태, 단가×객실×박수=전체 비용: 복수 번호, 골프 PAX 단가, 서로 다른 숙박일수, 부분 결제와 변경 이력이 있어 유형별 파서·검토가 필요하다.
- 배경색 범례: 엑셀만으로 모든 색의 업무 뜻을 확정할 수 없다. 샘플 행/셀별 의미를 업무 담당자와 검증한 후 상태 규칙에 반영한다.

## 8. 구현 산출물 순서

1. DB 마이그레이션과 원본 보존 테이블, 유일 제약/인덱스 확정. source_rows(batch_id,sheet,row)와 출처 FK 중심.
2. 시트별 파서와 메모/색 파서 작성. 실제 좌표 기반 회귀 fixture를 사용하고 각 추출 값에 출처·확신도·원문을 반환.
3. 가져오기 미리보기 및 검토 큐를 먼저 구현한 뒤 확정 데이터만 운영 테이블에 반영.
4. DB 스키마에서 타입을 생성하고 예약·일정·결제 입력 폼의 타입/검증을 공유. 자동 생성 코드는 필드/API 타입에 한정하고 메모·색 의미 판정은 검증 가능한 규칙으로 구현.
5. 1차 이관 검증 후 업무 화면과 정산 규칙을 순차 구현. 원본과 구조화 결과의 건수·금액 차이를 검토 화면에서 확인.

## 9. 필리핀·태국·일본 시스템 분리

- 웹앱은 하나의 통합 시스템이다. 로그인, 상단/측면 탐색, 목록·상세·캘린더·정산·원본 검토 화면의 디자인과 조작 방식을 통일한다. 사용자는 통합 화면에서 필리핀·태국·일본 시스템을 선택하거나 권한에 따라 여러 시장을 함께 조회한다.
- 공통 기반은 사용자/권한, 원본 이관·출처, 예약 식별자, 일정·비용·결제 이벤트, 감사 로그다. 화면 컴포넌트와 기본 입력 흐름을 공유하고 시장별 필드·용어·검증·상품·요금·정산·취소 규칙만 시장 설정 및 규칙 모듈로 분리한다. PH 규칙을 JP에 상속하거나 TH 규칙을 추측하지 않는다.
- markets 테이블에 PH/TH/JP를 등록하고 reservations에 market_id, itinerary_items에 service_market_id를 둔다. 일본 원장 일부 코드가 NEW 2026.xlsx의 통합 원장에도 있으므로 파일명만으로 국가를 결정하지 않는다. source_rows에는 추정 시장과 확정 시장을 따로 둔다.
- 동일 코드라도 시장·손님·행사일·거래처·출처를 비교해야 한다. 파일 간 동일 예약 후보는 reservation_sources로 연결하고 중복 매출 집계는 검토 완료 후에만 해결한다. 일본 원장과 기존 통합 원장의 코드 정확 일치가 5개 확인됐다.
- 태국은 별도 데이터와 업무 규칙이 아직 없으므로 시장만 예약해 두고 실제 파서·정산 로직은 만들지 않는다.

### 통합 UI 원칙

- 공통 예약 목록·상세 레이아웃을 쓰고 시장 선택에 따라 해당 국가의 항목을 표시한다. 예를 들어 일본은 손님 명단, 호텔 확인번호, 엔화 요금, 차량/미팅·샌딩 항목을 추가로 보여준다.
- 상태 배지와 색 체계는 웹앱 전체에서 같은 의미를 갖도록 정의한다. 원본 Excel 배경색은 별도 원본 보기에서 재현하고, 의미가 확인된 경우에만 업무 상태로 변환한다.
- 통합 대시보드에서 시장별 건수·금액을 필터링할 수 있다. 서로 다른 통화를 같은 합계로 더하지 않고 통화별 또는 명시된 환율 기준으로 표시한다.
- 공통 UI의 저장·검색·검토 동작은 같게 유지하고, 시장별 필수 입력값과 계산은 규칙 버전으로 관리한다. 새 시장을 추가해도 기본 화면을 복제하지 않는 구조를 목표로 한다.

### 일본 파서·검토 규칙

1. 일본 main의 G 코드와 cancle의 F 코드는 열이 한 칸 다르다. 두 시트의 5개 공통 코드를 출처 연결 후보로만 다룬다. cancle 시트 앞부분의 복사 행은 자동 취소하지 않는다.
2. 일본의 JPY, KRW와 예외적인 PHP 언급을 거래별 통화로 저장한다. 엔화 단가와 원화 청구액 사이 환산은 적용 환율·일자가 확인된 경우만 계산한다.
3. P:S 일정 문장 하나에서 골프장·복수 티오프·미팅·샌딩·기본 요금·점심/카트/락커·추가 요금·예약 상태를 복수 이벤트/비용으로 추출한다. OK 문구나 녹색 배경만으로 결제 완료를 뜻한다고 보지 않는다.
4. F열 손님 명단과 M열 호텔 확인번호는 개인정보/예약정보다. 원본 메모를 보존하고 운영 화면에서는 역할별 접근 권한을 적용한다.
5. 색칠된 빈 셀(main 9,991개, cancle 995개), 숨김 행, 병합 범위, 조건부 서식을 원본 보기에 재현한다. 색의 업무 의미는 일본 업무 규칙으로 별도 검증한다.
